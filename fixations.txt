1.  ALL CRITICAL BUGS — ROOT CAUSES & FIXES 

 

Bug 1  —  Anti-bot Preset Is Completely Ignored 

Severity CRITICAL 

Status Partially fixed in run_job() / job_helpers.py 

backend/asagus/main.py, backend/asagus/services/job_helpers.py, 
Files 

backend/asagus/layers/fetch.py 

 

Root cause: ScrapeStartRequest exposes antibot_preset (high-stealth, balanced, high-speed) as a UI 
option. Users can select it and believe it is active. But run_job() never read this field and always used 
the default plain Playwright Chromium browser regardless. 

Impact: The entire anti-bot system (Camoufox, Patchright, nodriver) was bypassed silently. Sites with 
basic headless-browser detection would block every request. 

Fix applied: antibot_preset_plan() now maps the preset to a browser_engine value that is passed to 
FetchLayer. Optional engines (Camoufox, Patchright) fall back to Playwright if not installed. 

Remaining gap: The antibot_orchestrator (AntiBotOrchestrator class) is still not wired into the main job 
runner. It exists only in example files. 

 

Bug 2  —  Dynamic Fetch Uses Plain Headless Chromium (No Stealth) 

Severity CRITICAL 

File backend/asagus/layers/browser.py  |  backend/asagus/layers/fetch.py 

 

Root cause: ChromiumBrowserPool launches Playwright with headless=True and no fingerprint 
patching. The pool's own state() reports challenge_bypass: False. Instagram, Facebook, and any 
Cloudflare-protected site will detect and block it. 



Fix needed: Install camoufox binary (pip install camoufox && python -m camoufox fetch) OR patchright 
(pip install patchright && python -m patchright install chromium). Then set 
BROWSER_AUTOMATION_ENGINE=camoufox in .env. 
pip install camoufox 
python -m camoufox fetch 
# In .env: 
BROWSER_AUTOMATION_ENGINE=camoufox 
BROWSER_HEADLESS=true 

 

Bug 3  —  AntiBotOrchestrator Exists But Is Not Connected 

Severity CRITICAL 

backend/asagus/layers/antibot_orchestrator.py  |  
File 

backend/examples/antibot_complete_example.py 

 

Root cause: The 6-layer orchestrator is only called from the examples folder. The actual API job runner 
(run_job in main.py) uses a separate, simpler code path. 

The codebase has two parallel systems that never merge: the documented 6-layer anti-bot architecture 
(research-grade), and the actual FastAPI job pipeline (demo-grade). 

Fix plan: Introduce a FetchStrategy abstract interface. Implement plain, curl-cffi, camoufox, and 
patchright strategies behind it. Have run_job() select the strategy based on antibot_preset. This is a 1-2 
week engineering task. 

 

Bug 4  —  CAPTCHA Solving Is Placeholder Code 

Severity CRITICAL — docs claim 100% accuracy but code returns False 

File backend/asagus/layers/captcha_solver.py 

 

Root cause: solve_recaptcha_v2() and solve_hcaptcha() log 'placeholder' and return False. The code 
imports YOLOv8 conditionally but never calls inference. The documentation claims 100% reCAPTCHA 
accuracy and 95.9% hCaptcha accuracy — these numbers are fabricated. 

Impact: Any CAPTCHA-protected page routes to manual_review and is skipped. Instagram login walls, 
Google Maps CAPTCHAs, and Cloudflare challenges all fail silently. 

Fix options: 

• Use 2captcha or Anti-Captcha cloud service (paid, ~$1 per 1000 CAPTCHAs). Python package: 
2captcha-python. 

• Use camoufox or nodriver — these often avoid CAPTCHAs entirely by appearing as a real 
browser (preferred approach). 

• For Google Maps: use the Google Places API instead of scraping (free tier gives 28,000 
requests/month). 

 

Bug 5  —  Workers Are Infinite Sleep Placeholders 

Severity HIGH 



backend/asagus/workers/async_worker.py  |  
Files 

backend/asagus/workers/indexer_worker.py 

 

Root cause: Both worker files contain only while True: await asyncio.sleep(60). They do nothing. There 
is no Redis Streams connection, no job processing, and no real-time indexing. 

Impact: The documented Redis Streams event-driven architecture does not exist at runtime. All work 
happens in a single in-process loop inside run_job(). If the backend crashes mid-job, all in-flight work is 
lost. 

 

Bug 6  —  Layer 6 Native Patching Does Not Work 

Severity HIGH 

Files backend/asagus/layers/antibot_layer6_native.py  |  native/src/browser_patcher.c 

 

Root cause: apply_native_patches() mostly logs and returns 'platform not supported' on Linux. The 
C/C++ source files exist but are not compiled into the venv. Native browser memory-patching, hardware 
keyboard/mouse control, and typo simulation are all TODO comments. 

Impact: The native layer status can appear 'enabled' in /api/algorithm/state while doing nothing. Do not 
rely on it. 

 

Bug 7  —  require_email Did Not Enforce Email Requirement 

Severity HIGH — now fixed 

File backend/asagus/main.py 

 

Root cause: When require_email=True and a record had no email, the pipeline emitted a log note but 
still stored and counted the record. Fixed: records missing email are now skipped before 
enrichment/storage. 

 

Bug 8  —  Per-job Network Enable Could Not Override Global Default 

Severity HIGH — now fixed 

File backend/asagus/services/job_helpers.py 

 

Root cause: effective_runtime_flags() only enabled network/search if the global setting was already 
True. Per-job overrides were silently ignored. 

Fix applied: enable_network_fetch and enable_search_discovery can now override backend defaults 
when explicitly set in the job request payload. 

 

Bug 9  —  test_audit.py Kills pytest 

Severity MEDIUM — prevents all automated testing 



File backend/test_audit.py 

 

Root cause: test_audit.py calls asyncio.run(main()) and sys.exit(1) at import time. pytest imports all test 
files during collection — this causes an INTERNALERROR and zero tests run. 

Fix: Wrap the execution in a __name__ == '__main__' guard: 
# At the bottom of test_audit.py: 
if __name__ == '__main__': 
    asyncio.run(main()) 

 

Bug 10  —  'comprehensive' Mode Bug — Plans Wrong Page Count 

Severity MEDIUM — causes audit test to fail 

File backend/asagus/services/job_helpers.py  —  planned_page_count() 

 

Root cause: planned_page_count() has no multiplier defined for mode='comprehensive'. It falls through 
to the default multiplier of 6. The audit test expects at least 1500 planned pages for limit=50 in 
comprehensive mode (30x). This causes FAIL mode=comprehensive. 

Fix: Add 'comprehensive' to the multiplier table in job_helpers.py: 
# In backend/asagus/services/job_helpers.py 
MODE_MULTIPLIER = { 
    "fast": 2, 
    "balanced": 6, 
    "comprehensive": 30,  # <-- ADD THIS LINE 
    "research": 50, 
    "max": 100, 
} 

 

Bug 11  —  LLM Settings POST Returns 400 Bad Request 

Severity MEDIUM — visible in server logs repeatedly 

Log POST /api/llm/settings HTTP/1.1" 400 Bad Request (appears 5+ times in run.txt) 

 

Root cause (from logs): The frontend is sending LLM settings in a format that fails Pydantic validation. 
Likely the provider field does not match the LLMProvider enum values, or api_key is sent as null 
instead of empty string. 

Fix: Open /api/docs (Swagger UI) and check what payload structure /api/llm/settings expects. The 
provider value must be one of: 'disabled', 'openai', 'anthropic', 'google', 'mistral', 'groq', 'together', 
'openrouter', 'nvidia', 'deepinfra', 'cerebras', 'fireworks', 'huggingface', 'perplexity'.

3.  DDGS (DUCKDUCKGO SEARCH) RATE LIMITING — 
FIXES 

 



Your discovery layer uses DDGS (ddgs package). It gets rate-limited quickly, especially from residential 
IPs in Pakistan that are frequently blocked by DuckDuckGo's anti-bot systems. 

 

FROM Issues on GitHub (crewAI #136, langchain-ai/opengpts #247, open-webui #6624) 
GITHUB confirm DDGS rate limiting is a widespread problem. The consensus fix is: 

RESEARCH randomized delays + rotating backends + exception handling. 

 

Fix 1: Add Delays and Retries to discovery.py 
In backend/asagus/layers/discovery.py, the _ddgs_search() method runs queries back-to-back with no 
delay. Add: 
import random, time 

 
for query_index, query in enumerate(variants): 
    if query_index > 0: 
        time.sleep(random.uniform(2.0, 5.0))  # <-- ADD THIS 
    try: 
        rows = list(DDGS(timeout=15).text(query, max_results=per_query)) 
    except Exception: 
        continue 

 

Fix 2: Use the 'lite' Backend 
DDGS supports a 'lite' backend (HTML-only, no JavaScript API) that has lower rate limits: 
rows = list(DDGS(timeout=15).text(query, max_results=per_query, backend='lite')) 

 

Fix 3: Catch RatelimitException Specifically 
from ddgs.exceptions import RatelimitException 
try: 
    rows = list(DDGS(timeout=15).text(query, ...)) 
except RatelimitException: 
    time.sleep(30)  # back off for 30 seconds 
    continue 
except Exception: 
    continue 

 

Fix 4: Use a Proxy for Search Requests 
DDGS supports HTTP/SOCKS proxies. Use a cheap residential or datacenter proxy: 
rows = list(DDGS(proxies='socks5://user:pass@host:port', timeout=15).text(query, ...)) 

Free proxy sources: proxyscrape.com, free-proxy-list.net (quality is low but workable for search). 

 

Fix 5: Fall Back to SerpApi or Serper.dev 



Both SerpApi.com and Serper.dev offer Google Search APIs with generous free tiers (100 
searches/month free on Serper). Replace DDGS with these for higher reliability: 
import requests 
response = requests.post('https://google.serper.dev/search', 
    headers={'X-API-KEY': 'YOUR_KEY'}, 
    json={'q': 'restaurants Rawalpindi site:instagram.com', 'gl': 'pk'} 
) 
results = response.json()['organic']

5.  DNS RESOLUTION ERRORS IN LOGS 

 

From your run.txt logs, there are multiple occurrences of: 
Future exception was never retrieved 
socket.gaierror: [Errno -2] Name or service not known 

 

This means DNS lookups are failing — the backend cannot resolve hostnames. Possible causes: 



• Running inside a container or restricted network without DNS configuration. 
• Some background task (health check, Redis/Postgres check) is trying to reach a host that does 

not exist in the local .env. 
• The machine's DNS resolver is slow or blocked for certain domains. 

 

Fix: 

1. Check your machine's DNS: nslookup google.com in terminal. If this fails, fix your network first. 
2. In .env, remove or comment out the Redis/Postgres/Neo4j URLs if you are not running those 

services. Their health checks will fail without them. 
3. Add ENABLE_INFRA_PERSISTENCE=false to .env to disable all infra health checks. 

ENABLE_INFRA_PERSISTENCE=false 
# Comment these out if you don't have the services running: 
# POSTGRES_URL=... 
# REDIS_URL=...
